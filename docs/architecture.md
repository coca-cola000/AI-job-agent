# AI 求职自动化项目设计

## 1. 项目目标

构建一个个人使用的 AI 求职助手，减少整理职位、比对要求、准备材料和记录进度的重复工作，让用户把时间用于选择机会和准备面试。

初版以“导入职位 → 分析匹配 → 准备材料 → 人工提交 → 跟踪进度”为完整流程。优先保证结果可检查、数据不丢失、操作可恢复。

目前没有现有业务资料或技术实现，本文采用以下初版假设：单人使用、本地运行、用户提供简历和职位信息。目标招聘平台、部署方式和预算在开发前确认；这些问题不影响先实现核心流程。

## 2. 用户需求

| 需求 | 初版行为 | 完成标准 |
| --- | --- | --- |
| 管理个人资料 | 保存简历、技能、项目经历和求职偏好 | 用户能查看、修改和导出自己的资料 |
| 整理职位 | 粘贴职位正文，附上来源链接 | 保存公司、职位、要求、来源和导入时间；缺失信息允许留空 |
| 判断匹配程度 | 比对职位要求与个人经历 | 展示匹配点、差距、引用依据和需要确认的信息 |
| 准备申请材料 | 生成简历调整建议及求职信草稿 | 用户能编辑和导出；内容不得虚构经历 |
| 跟踪申请 | 记录准备中、已投递、面试中、录用、拒绝、已关闭 | 每次状态变化有时间和备注 |
| 安排下一步 | 保存跟进日期和待办事项 | 在界面中看到到期任务，避免遗漏 |

初版成功标准：用户能完成一次真实申请的全流程；关闭并重新打开后记录仍然完整；AI 失败时仍能整理职位和维护申请进度。

## 3. 系统边界

### 纳入初版

- 单用户个人资料和求职偏好管理。
- 手动导入职位正文及链接，人工修正提取结果。
- AI 辅助匹配分析和申请材料起草。
- 申请状态、备注和跟进日期管理。
- 数据导出、备份和恢复。

### 暂不纳入

- 大规模职位抓取、自动登录招聘平台、验证码处理。
- 自动批量投递、自动发送邮件或代替用户与招聘方沟通。
- 多用户、团队协作、复杂权限和付费体系。
- 微服务、消息队列、向量数据库、复杂的多智能体流程。

系统负责提供建议和草稿；用户负责核实真实性、决定申请对象并提交材料。生成草稿不能自动将申请标记为“已投递”。

## 4. 技术方案

### 整体结构

使用单体应用：一个本地网页界面、一个应用服务、一个 SQLite 数据库。界面和服务在同一项目中维护，优先选开发者熟悉的成熟框架。

运行路径：用户界面 → 应用服务 → 本地数据库。需要分析或起草时，由应用服务调用一个 AI 服务。

初版不需要独立任务队列。AI 请求由用户主动触发，界面显示处理中、成功或失败；失败后允许人工重试。只有出现明确的耗时或并发问题时，再引入后台任务。

### 功能划分

按功能组织代码即可，不拆成独立服务：

- **个人资料**：管理事实信息和求职偏好。
- **职位管理**：保存原文、来源和结构化字段，提示可能重复的职位。
- **AI 辅助**：提取字段、分析匹配、生成材料草稿。
- **申请跟踪**：维护申请记录、状态历史和跟进日期。
- **数据管理**：导出、备份和恢复。

### 核心数据

| 数据 | 主要内容 |
| --- | --- |
| 个人资料 | 简历正文、技能、经历、偏好、更新时间 |
| 职位 | 公司、名称、来源链接、职位原文、结构化要求、导入时间 |
| 匹配分析 | 对应职位、匹配点、差距、依据、分析时间、使用的模型及提示词版本 |
| 材料草稿 | 对应职位、材料类型、正文、草稿版本、用户确认状态 |
| 申请记录 | 对应职位、当前状态、状态历史、备注、跟进日期 |

职位原文和用户修改后的字段都要保存。分析结果及草稿应记录生成时使用的资料和职位快照，避免用户后来修改资料后，旧结果看起来仍然有效。初版无需设计通用版本管理系统。

### 可靠性与隐私

- 数据库是事实记录的来源；AI 输出作为待核实的建议保存。
- 匹配分析优先展示具体要求与经历的对应关系，不使用缺乏依据的精确分数。
- AI 返回内容先校验必需字段；缺失或格式错误时显示失败，不覆盖已有有效结果。
- 网络请求设置超时，不无限重试；用户重试时避免生成重复申请记录。
- 外部 AI 只接收当前任务必需的信息，默认去除联系方式等无关个人信息；首次使用时说明发送范围。
- AI 密钥保存在服务端配置中，不进入浏览器、数据库导出或日志。
- 职位正文作为待分析数据处理，不能用其中的指令触发操作或改变系统规则。
- 初版本地服务仅供本机访问；公开部署前再补充登录、访问控制和传输保护。
- 提供手动备份和恢复。数据库与材料文件一起备份，开发验收时实际执行一次恢复。

## 5. 数据流

### 主流程

1. **录入资料**：用户提供简历和偏好，检查后保存为个人资料。
2. **导入职位**：用户粘贴正文及来源链接，先保存原文；提取字段后由用户修正。
3. **分析匹配**：读取个人资料和职位要求，发送最小必要内容给 AI；校验并保存匹配点、差距和引用依据。
4. **生成材料**：结合真实经历与目标职位生成草稿；用户检查、编辑并导出。
5. **提交申请**：用户在招聘平台或邮件工具中提交，再手动记录“已投递”。
6. **跟踪结果**：用户更新面试、录用等状态，填写备注和下一次跟进日期。

### 失败处理

| 情况 | 处理方式 |
| --- | --- |
| 职位信息不完整 | 保留原文，标注缺失字段，允许人工补充 |
| AI 服务不可用 | 保留已录入数据，提示重试，继续支持手动操作 |
| AI 内容无依据 | 标注需要确认，不把推测写入个人资料 |
| 重复导入 | 根据来源链接及公司、职位名称提示重复，由用户决定保留或更新 |
| 保存失败 | 明确提示未保存，保留界面输入，允许重试 |
| 资料或职位发生变化 | 提示旧分析和草稿需要重新检查，重新生成时保留旧版本 |

## 6. 后续开发路线

按可验收的阶段推进，不提前建设尚未需要的基础设施。

### 第一阶段：基础记录

实现个人资料、手动职位导入、职位列表、申请状态和备注。先建立稳定的数据存储与导出能力。

**验收**：不依赖 AI，也能整理多个职位并跟踪申请；重启后数据完整。

### 第二阶段：AI 辅助

接入一个 AI 服务，实现职位字段提取、匹配分析和材料草稿。补充输出校验、超时处理、错误提示及资料快照。

**验收**：用真实职位完成一次分析和草稿生成；能核对依据；断网或异常输出不会破坏原有数据。

### 第三阶段：完整求职流程

完善材料编辑和导出、跟进日期、到期待办、重复职位提示，以及备份恢复。

**验收**：完成一次从导入到人工投递再到跟进的真实流程，并验证备份可恢复。

### 第四阶段：按实际需求扩展

根据使用反馈决定是否增加职位链接解析、简历文件导入、更多 AI 服务或提醒通知。招聘平台接入逐个平台评估；只有平台提供适用接口且用户需要时，才考虑提交申请的自动化，并保留提交前确认。

**扩展原则**：先确认具体问题和收益，再增加能力。每项扩展都应保留手动操作路径，不影响已有数据和核心求职流程。
